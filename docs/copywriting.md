# Тексты Finiq

Русский и английский тексты интерфейса находятся в `src/i18n/messages.ts`. Таблица копирайтера содержит листы `RU` и `EN`: одна строка на ключ, текущий текст, новая версия, статус, комментарий, переменные и контекст. Оба языка редактируются независимо и одинаково в жёлтых столбцах D–F. Столбец H содержит только справочную копию другого языка.

## Работа с таблицей

1. Автор заполняет «Новый текст» и ставит «На согласовании».
2. Проверяющий ставит «Согласовано». Если текущий вариант принят, ставит «Без изменений».
3. Разработчик получает `.xlsx`, сначала проверяет изменения, затем применяет их.

В Excel защищены все ячейки, кроме D–F со строками текстов на листах RU и EN. Защищена и структура книги: нельзя случайно удалить или переименовать лист. Фильтры и изменение высоты строк разрешены; сортировка, вставка и удаление строк заблокированы. Пароль для команды: `finiq-copy`. Это защита от случайных изменений, а не разграничение ролей: статус «Согласовано» технически может поставить любой редактор.

Пустая новая версия не удаляет текст. Комментарии не импортируются. При переносе в Google Таблицы владелец должен отдельно настроить и проверить защиту диапазонов; настройки защиты Excel не считаются гарантией ограничений в другом редакторе. Для импорта скачать результат как `.xlsx`.

## Адреса экранов и API

Столбец K указывает основные экраны использования, L — связанные API-методы раздела. Это справочный контекст, а не привязка отдельной строки к запросу и не полный перечень фоновых запросов. Общие компоненты и локальные действия могут не иметь собственного API. Текст всё равно сопоставляется по ключу и языку.

Пути экранов относительны к `VITE_FINGUIDE_BASE_PATH` (например, `/fg/` + `goals`). Пути API — к `VITE_FINGUIDE_API_BASE_URL`, по умолчанию `/finguide-api/api/v1`. `{OIDC_ISSUER}` обозначает `VITE_FINGUIDE_OIDC_ISSUER_URL`. Значения `{planId}`, `{id}`, `{year}` и `{years}` — параметры адреса, их нельзя переносить в текст интерфейса как переменные перевода.

Карта находится в `scripts/copy-context.mjs`; её нужно сверять с `src/router.tsx`, `src/api/backendPlanClient.ts` и `src/auth/` при изменении маршрутов. `copy:catalog` также возвращает поля `screens` и `api`.

Сохранять точное написание и количество переменных `{{year}}`, `{{count}}`, `{{brand}}` и других. Переставлять их можно. Формулы вместо текста не поддерживаются.

## Импорт

Из корня репозитория:

```bash
bun run copy:import /absolute/path/Finiq-copy-RU-EN.xlsx
bun run copy:import /absolute/path/Finiq-copy-RU-EN.xlsx --write
git diff -- src/i18n/messages.ts
bun run typecheck
bun run test
```

Первая команда только показывает правки. Вторая применяет все согласованные строки после успешной проверки всего файла. Импорт сопоставляет ключи и язык, а не номера строк. Существующее форматирование TypeScript и комментарии сохраняются, меняются только строковые литералы.

Импорт отклоняет неизвестные и повторяющиеся ключи, неверные статусы, формулы, пустой согласованный текст, изменения переменных и конфликт с текущим исходником. Имена листов пользовательского экспорта также проверяются на ограничения Excel. Уже применённые правки пропускаются. Несогласованные версии остаются в таблице и не попадают в код.

После импорта проверить изменённые экраны на обоих языках: техническая проверка не заменяет проверку смысла и длины текста.

```bash
bun run copy:test
bun run copy:catalog > /tmp/finiq-copy-catalog.json
```

`copy:catalog` выгружает актуальные ключи, обе версии, переменные и номера строк для обновления таблицы. Это JSON с исходными данными, не замена рабочему Excel.

## Название продукта

Единственная настройка отображаемого названия — `brand.name` в `src/config/brand.ts`. Сейчас это `Finiq`.

В переводах писать `{{brand}}`, например `«{{brand}} поможет…»`. Переводчик автоматически подставляет настройку; компоненты не передают название вручную. Из этой же настройки формируются подпись логотипа, HTML title/description, webmanifest, автор и имя файла Excel-экспорта. После переименования приложение нужно пересобрать.

Старые технические идентификаторы `finguide` в API URL, OIDC client/realm, переменных окружения и ключах localStorage остаются совместимыми с существующей инфраструктурой и данными. Старые SVG с нарисованным словом FinPlan больше не используются как подпись логотипа: название рендерится текстом рядом с иконкой.

## Добавление текстов

- Добавлять ключ сразу в `ru` и `en`, с одинаковыми переменными.
- Тексты с числом («1 год / 2 года / 5 лет») хранят три формы: `one`, `few`, `many` (например, `goals.inYears.one`). Форма выбирается по параметру `count`: `t("goals.inYears", { count })`. В английском `few` и `many` совпадают. В таблице каждая форма — отдельная строка; менять нужно все три.
- В React использовать `useI18n().t`. Для форматирования чисел — `useFormat()`.
- В коде вне React использовать `createTranslator(locale)` с явным языком. `translateCurrent` предназначен для значений по умолчанию, создаваемых в момент операции.
- Отображать `LocalizedError` через `errorMessage(error, t)`. Диагностическое сообщение API не выводить пользователю напрямую.
- Не переводить введённые пользователем названия планов, целей и заметки.

Словарь покрывает React-фронтенд, его служебные страницы, формы и экспорт. Отдельные backend-шаблоны Keycloak хранят тексты в своих `.properties`; они не импортируются этим инструментом. При проверке 24.09.2026 в `finguide-be/deploy/keycloak/themes/finguide/` и `configure-realm.py` найдены старые названия FinGuide/FinPlan. Поэтому локализация React-приложения не означает завершённую проверку всех экранов сервиса, писем и внешней авторизации. Развёрнутый Keycloak в этой задаче не проверялся.

В локальной backend-ветке есть отдельные методы `GET /ui-texts/{locale}`, `GET /ui-texts/{locale}/draft`, `PUT /ui-texts/{locale}/draft`, `POST /ui-texts/{locale}/publish`. Текущий React-фронтенд их не вызывает, а Excel-импорт изменяет локальный словарь. Эти методы не следует представлять как уже подключённый путь публикации копирайтинга.

Строка `WHATIF_SCENARIO_NAME` в API-клиенте — сохранённый идентификатор старого сценария, а отображаемое название берётся из словаря. Менять идентификатор через копирайтинг нельзя: это нарушит поиск существующих сценариев.

Проверки RU/EN, переменных, бренда, ошибок и экспорта находятся в тестах. Браузерная проверка:

```bash
VITE_FINGUIDE_AUTH_ENABLED=false VITE_FINGUIDE_BASE_PATH=/ bun run dev -- --host 127.0.0.1 --port 5174
# В другом терминале; при необходимости указать PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH.
bun run e2e tests/e2e/localization.spec.ts --project=chromium
```
